# Architecture and maintenance notes

The package has four main parts. The live effect does not load the pitch model,
and the MIDI trigger does not use pitch features. Live control depends on the
effect process and communicates with it through a local socket.

| Path | Modules | Flow |
| --- | --- | --- |
| Live effect | `alsa_pcm.py`, `effect.py`, `processing.py` | ALSA mono PCM capture → overdrive/clean crossfade → ALSA playback |
| Live control | `control.py`, `footswitch.py`, `demo_ui.py` | Local Unix socket commands → effect state; GPIO and localhost HTTP UI are optional clients |
| Offline classifier | `dataset.py`, `audio.py`, `features.py`, `model.py`, `streaming.py`, `cli.py` | Labeled WAV → mono segment → features → KNN training, prediction, or benchmark |
| MIDI trigger | `audio_to_midi.py` | `arecord` RMS threshold → fixed MIDI note on/off |

## Live path

`effect.py` selects ALSA devices, validates effect settings, opens capture and
playback with `AlsaPcm`, and processes each block through `SwitchableEffect`.
`processing.py` applies tanh overdrive and a one-pole low-pass tone filter.
Clean/effect changes crossfade over 10 ms. `control.py` serves commands on
`/run/guitar-effect.sock`; `mode` sends `status`, `clean`, `effect`, or
`toggle`. The browser UI also uses internal `state` and `amount <0..1>` socket
commands. The socket is local to one machine and is removed on normal shutdown.

The browser server binds only to `127.0.0.1`. Its endpoints are
`GET /api/state`, `POST /api/mode` with `{"enabled": true|false}`, and
`POST /api/amount` with `{"amount": 0..1}`. `demo_ui.py` starts a default
effect process only if no existing control socket responds. The server has no
authentication; access it locally or through an SSH tunnel.

## Classifier path

`dataset.py` derives labels from standard-tuning string/fret filenames.
`audio.py` reads an integer-PCM WAV segment, averages channels, removes DC
offset, and uses integer decimation. `features.py` estimates fundamental pitch
with a YIN-style method and produces ten features: estimated MIDI pitch,
cents offset, confidence, log RMS, zero-crossing rate, crest factor, and four
harmonic values.

`model.py` standardizes and weights the features for KNN. It narrows
candidates with per-label prototypes, then uses inverse-distance voting.
`train` evaluates a seeded per-label holdout and fits the saved JSON model on
all examples. The JSON contains feature metadata, normalization values,
prototypes, and training examples; loading checks feature names against the
running code. Regenerate models after incompatible feature changes.

`benchmark` times prediction on preloaded signals and on overlapping frames
generated by `streaming.py`. Optional `--include-io` adds WAV reading to a
separate measurement. Neither benchmark runs ALSA capture or schedules frames
in real time.

## Local artifacts and verification

`data/` and `models/` are ignored by Git. `models/clean_pitch_knn.json` is the
default model path, not a source file. Back up recordings and trained models
separately if needed. Run `uv run python -m unittest discover -s tests` after
changes. Tests are algorithmic and local-socket based, so check ALSA, GPIO,
MIDI, and SSH/UI behavior manually on the target Pi.
