# Live audio and control

`pedal-engine` runs the ALSA audio loop and polls a local Unix socket. The command protocol supports `state`, `status`, `clean`, `effect`, `toggle`, `amount N`, `board ID,ID`, `config ID SETTING VALUE`, `lv2-list`, and `lv2-load URI`. A board of `-` clears the active chain. Board IDs must be unique and known to the engine; `amount` ranges from 0 to 1. `pedalctl` sends commands directly. `state` returns JSON, while `status`, `clean`, `effect`, and `toggle` return the mode as plain text. Invalid commands return an `error:` line and a nonzero `pedalctl` exit code. Set `PEDAL_CONTROL_SOCKET` in the engine and each client to change the default socket path.

`pedal-web` serves the browser panel on loopback and translates JSON requests to the same socket commands. Its read endpoints are `GET /api/state`, `GET /api/lv2`, and `GET /api/midi`. Its write endpoints are `POST /api/board`, `/api/config`, `/api/import`, `/api/mode`, `/api/amount`, and `/api/tuner`. Rejected JSON or engine settings receive HTTP 400; an unavailable engine receives HTTP 503.

The engine also supports `tuner on`, `tuner off`, and `midi-events`. `state` includes a `tuner` object with note, frequency, cents, confidence, and enabled fields, plus MIDI queue counts. `midi-events` returns and drains queued messages. The browser uses `POST /api/tuner` to change tracking and `GET /api/midi` to read events.
