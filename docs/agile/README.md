# Agile plan

The current product vision is kept in three workbooks in this directory:

| Workbook | Use |
| --- | --- |
| [Project backlog](project-backlog.xlsx) | Thirty Raspberry Pi pedal outcomes, dependencies, and acceptance evidence. Owner and status are blank until assigned. |
| [Sprint backlog](sprint-backlog.xlsx) | Proposed assignment of every project ID to a phase. Its `ESOF timeline` sheet records all twelve ESOF 423 entries and due dates read from the laptop's `todo` command on October 9, 2026. |
| [Burndown](burndown.xlsx) | Planned remaining unweighted backlog items by phase. Actual remaining is blank until sprint reviews supply it. |

The vision covers a guitar audio interface, Raspberry Pi, dedicated GPIO circuit and PCB, screen and player UI, 3D-printed case, presets, multiple effects including a trained ML audio effect, and a reliable assembled product. The 30 ms immediate minimum acceptable product target is proposed for the December 4 Production Readiness checkpoint. The 10 ms long-term goal has no ESOF due date and is shown after the course timeline. Neither target is marked achieved; the product-latency measurement method still needs to be recorded.

ESOF dates are source milestones. Placement of product work against them is a proposal, and course-only items such as the Playwright exercise and presentation attendance do not count as product acceptance. The burndown counts items equally because no effort estimates were supplied. If sprint assignments change, update the planned item counts in the burndown. Enter actual remaining only after a review.

Earlier spreadsheet snapshots and the undated vision remain recoverable from Git history. The three files above are the current planning artifacts.
